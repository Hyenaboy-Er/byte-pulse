# Claude-Regeln für byte-pulse — non-negotiable

Diese Regeln sind operative Pflicht, nicht Empfehlung. Bei Verstoß: User
informieren, sofort fixen.

## Vor JEDEM Push

1. **`npm run typecheck`** lokal ausführen (oder `npx tsc --noEmit`).
   - Wenn rot: NICHT pushen. Fix lokal.
2. Bei größeren Änderungen: zusätzlich `npm run build` lokal versuchen.
   - Auf Windows hilft `taskkill /F /IM node.exe` vorher gegen EPERM bei Prisma.

## Nach JEDEM Push

3. **Vercel Deploy-Status prüfen** — nicht nur die URL:
   ```bash
   curl -s -H "Authorization: Bearer $VERCEL_TOKEN" \
     "https://api.vercel.com/v6/deployments?projectId=byte-pulse&limit=1" \
     | python -c "import json,sys; d=json.load(sys.stdin); print(d['deployments'][0]['state'])"
   ```
   Erwartet: `READY` nach ~2-4 Min. Bei `ERROR`: sofort Logs holen + fixen.
4. Background-Watcher der "URL antwortet HTTP 200" prüft ist NICHT genug —
   die alte Version läuft weiter wenn der neue Deploy scheitert.

## Pre-Push-Hook gesetzt (2026-06-03)

`.husky/pre-push` ruft `npx tsc --noEmit` auf. Wenn TS rot → Push wird abgelehnt.

**Bypass nur bewusst:**
```bash
git push --no-verify    # nur für doc-only changes
```

## Build-Check GitHub Action gesetzt (2026-06-03)

`.github/workflows/build-check.yml` läuft auf JEDEM Push zu main.
- Bei TS-Fehler oder Build-Fehler → Telegram-Alert
- Wenn der scheitende Commit von `byte-pulse-bot` kam (auto-snapshot)
  → automatischer Revert via GitHub.
- Erfolg nach vorheriger Fail-Kette → "Build green" Telegram-Ping.

## Vercel Webhook gesetzt (2026-06-03)

`/api/vercel-deploy-hook` empfängt Vercel Deploy-Events:
- Production-Error → 1 strukturierte Telegram-Nachricht (statt 6 Spam-Mails)
- Recovery (erster Success nach Fail) → "Site is healthy again"

Setup-URL: `https://www.byte-pulse.net/api/vercel-deploy-hook`
Env: `VERCEL_WEBHOOK_SECRET`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
